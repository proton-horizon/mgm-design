MGM Design / Guide

A small, private workspace.

Accounts use email and password. A site admin creates accounts and shares credentials directly. There are no invitation or password-reset emails.

First-time setup

The installation owner configures a secret setup key when deploying. The first visit asks for that key, an email, name, and a password of at least 12 characters. Successful setup permanently closes this route and signs in the first site admin.

People

Open Site administration → People to add viewers or site admins. Everyone can browse all projects on that installation. Admins also manage people, register projects, and replace publishing tokens. Reset a password and share it directly, or disable an account to remove access. Account changes invalidate its existing sessions.

Projects and tokens

Add a project using its display name and a stable lowercase ID matching its manifest. Copy the publishing token when it is shown; it cannot be revealed later. Store it using the source repository's existing secret system. Replacing it invalidates the previous publishing credential, so update the source workflow too.

How it works

The server stores password and credential hashes and checks access on every protected request. A publishing token can update only its own project. The browser uses a separate account session. Disabling an account or signing out also revokes that session's preview URLs.

For admin lockout, the owner can recover through privileged database access. See the backend recovery instructions. Do not reopen the bootstrap route.
