MGM Design / Guide

A small, private workspace.

Accounts use email and password. A site admin shares an invitation link so each person chooses their own password. Links are shared manually; the site does not send email.

First-time setup

The installation owner configures a secret setup key when deploying. The first visit asks for that key, an email, name, and a password of at least 12 characters. Successful setup permanently closes this route and signs in the first site admin.

Invite someone

  1. Open Site administration → People.
  2. Enter their name and email, choose Viewer or Site admin, and select Create invite.
  3. Copy the link and share it privately with that person. It works once and expires after seven days.
  4. They open the link, choose and confirm a password of 12–256 characters, then sign in.

Pending invitations appear under People. Revoke an invite there, or create another for the same email to replace its link or change its role. Links are only shown when created. If a recipient refreshes the password page before saving, they can reopen the original link.

Permissions

Viewers can browse and interact with every project on this site. Site admins can also invite people, change roles, disable accounts, register projects, and replace publishing tokens. Use the role selector beside an existing account to switch between Viewer and Site admin. You cannot disable or demote yourself; an enabled site admin must remain. Account edits sign that person out. Disabling or demoting an admin also revokes links they issued.

Change your password

Open Change password in the sidebar. Enter your current password, then enter and confirm your new one. On mobile, open the top-left menu to find it. Every account has this option.

Forgotten passwords

Ask a site admin for a reset link. In Site administration → People, the admin selects Create reset link beside an enabled account, then copies and shares it privately. The recipient chooses their own password. The link works once, expires after one hour, and replaces any previous reset link. Existing accounts use this flow rather than a new invite.

Creating a reset link leaves the current password working until it is used. After a password change or reset, all of that account’s sessions and remaining reset links stop working; sign in again with the new password.

Treat links like passwords. Anyone holding one can set the intended account’s password. Share only with the intended person. Invalid, used, revoked, or expired links require a fresh link from a site admin.

Projects and tokens

Add a project using its display name and a stable lowercase ID matching its manifest. Copy the publishing token when it is shown; it cannot be revealed later. Store it using the source repository's existing secret system. Replacing it invalidates the previous publishing credential, so update the source workflow too.

How it works

The server stores password and credential hashes and checks access on every protected request. A publishing token can update only its own project. The browser uses a separate account session. Disabling an account or signing out also revokes that session's preview URLs.

For admin lockout, the owner can recover through privileged database access. See the backend recovery instructions. Do not reopen the bootstrap route.
